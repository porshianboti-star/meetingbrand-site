Teams background deployment · IT how-to

Deploy Teams backgrounds with Intune or Jamf — no Teams Premium

Microsoft Teams has no API for meeting backgrounds, so deploying a branded Teams background to every employee means putting the image on each device. MeetingBrand does that with the MeetingBrand Agent: IT deploys it once with the Intune (Windows) or Jamf (macOS) script generated in the app, and the Agent places the approved background in each person's Teams background gallery, where they select it once.

The procedure: deploy a branded Teams background with Intune or Jamf

  1. Approve the background in MeetingBrand. Open meetingbrand.com/app/, sign up with your work email and approve the room and sign treatment the company should use; MeetingBrand renders the 1920×1080 export the Agent will deliver.
  2. Add your people. My team → Upload users → upload a CSV with name, email, title and department. The Agent matches each device to a person by the signed-in e-mail.
  3. Generate the script with your enrollment key. My team → Agents → New enrollment key, then copy the Intune (Windows) or Jamf (macOS) script. The key is per tenant and appears in the script as <ENROLLMENT_KEY>; keep it out of tickets and chat.
  4. Deploy it once. Intune: Devices → Scripts → Windows 10 and later, run using the logged-on credentials, 64-bit PowerShell. Jamf: a policy that runs the shell script as the console user. The script downloads the Agent, verifies its sha256, registers a per-user scheduled task (Windows) or LaunchAgent (macOS) for logon and every 4 hours, and runs it once.
  5. Verify on a pilot device. After Teams restarts, %LocalAppData%\Packages\MSTeams_8wekyb3d8bbwe\LocalCache\Microsoft\MSTeams\Backgrounds\Uploads (macOS: ~/Library/Containers/com.microsoft.teams2/Data/Library/Application Support/Microsoft/MSTeams/Backgrounds/Uploads) holds <GUID>.png and <GUID>_thumb.png, and My team shows the person as delivered. Windows SmartScreen and macOS Gatekeeper prompt on the unsigned developer builds, so pilot with a small group first.
  6. Employees select it once. After Teams restarts, each person opens Effects and avatars → Backgrounds (Video effects in a meeting) and selects the branded background; Teams keeps it. A later rebrand swaps the bytes under the same GUID, so there is nothing to pick again.

What lands on each device: the script skeleton

New Teams lists a background only when <GUID>.png and a matching <GUID>_thumb.png sit in %LocalAppData%\Packages\MSTeams_8wekyb3d8bbwe\LocalCache\Microsoft\MSTeams\Backgrounds\Uploads (macOS: ~/Library/Containers/com.microsoft.teams2/Data/Library/Application Support/Microsoft/MSTeams/Backgrounds/Uploads). This is what the MeetingBrand Agent does there, redacted to a skeleton; the Intune or Jamf script generated in My team installs the Agent with your enrollment key, and the Agent runs this logic at logon and every 4 hours. Re-runs are idempotent: when the bytes already match, nothing is rewritten.

# What the MeetingBrand Agent does on each Windows device, as a PowerShell skeleton. The Intune or Jamf script generated in
# My team installs the Agent with your enrollment key; the Agent then runs this logic at logon and every 4 hours. Redacted: <...> are per tenant.
$OrgKey  = "<ENROLLMENT_KEY>"   # per tenant: MeetingBrand → My team → Agents → New enrollment key
$Uploads = "$env:LOCALAPPDATA\Packages\MSTeams_8wekyb3d8bbwe\LocalCache\Microsoft\MSTeams\Backgrounds\Uploads"   # the folder new Teams reads
New-Item -ItemType Directory -Force -Path $Uploads | Out-Null
# one approved background = one stable GUID and TWO files; without the _thumb, new Teams does not list it
$Guid  = "<GUID>"
$Png   = Join-Path $Uploads "$Guid.png"            # the 1920×1080 export
$Thumb = Join-Path $Uploads "$($Guid)_thumb.png"   # 280×158 thumbnail
$Want  = "<SHA256>"                                # announced by MeetingBrand for this export
if ((Test-Path $Png) -and ((Get-FileHash $Png -Algorithm SHA256).Hash.ToLower() -eq $Want)) { exit 0 }   # idempotent: same bytes, nothing to do
Invoke-WebRequest -Uri "<SIGNED_EXPORT_URL>" -OutFile "$Png.tmp" -UseBasicParsing
if ((Get-FileHash "$Png.tmp" -Algorithm SHA256).Hash.ToLower() -ne $Want) { Remove-Item "$Png.tmp"; throw "sha256 mismatch" }
Move-Item -Force "$Png.tmp" $Png                   # atomic swap: a rebrand replaces the bytes under the same GUID
Invoke-WebRequest -Uri "<SIGNED_THUMB_URL>" -OutFile $Thumb -UseBasicParsing
# Restart Teams. The employee picks the background once under Video effects — no script can switch the active background.

What the employee sees

Nothing happens until Teams restarts. Then the branded background is one more tile under Effects and avatars → Backgrounds (Video effects in a meeting), with the thumbnail the Agent wrote next to it. The person picks it once and Teams keeps it for later meetings; nothing switches their active background for them, because no meeting platform lets a third party do that by API. A later rebrand replaces the image behind the same tile, so there is nothing to pick again. The Agent builds are unsigned developer builds for now, so a person who double-clicks the binary in a browser download would see Windows SmartScreen or macOS Gatekeeper; the scheduled task runs it without that prompt.

Why Teams backgrounds are deployed to the device

Microsoft Teams has no API for meeting backgrounds. Outside Teams Premium, which lets an admin upload organization backgrounds in the Teams admin center, a custom image reaches Teams only from the person's own device.

That is why a do-it-yourself rollout usually ends in a script that copies image files to every laptop and has to be rewritten whenever the brand changes. The MeetingBrand Agent replaces that script: it brings the backgrounds you approve in MeetingBrand to each device, and later changes arrive without another deployment.

What the Intune or Jamf script does

The script is generated in My team and carries your organization's enrollment key. It installs the MeetingBrand Agent, a small helper for Windows and macOS; the Agent can also be installed by hand with the same key.

The Agent matches each device to a person by the signed-in e-mail, so people you added by CSV (name, email, title, department) are covered. After Teams restarts, the branded image appears under Effects and avatars → Backgrounds. My team shows each person's status: delivered, waiting for a restart, needs the employee's one click, or blocked (with the reason).

Before you roll it out

The Agent builds are unsigned developer builds for now, so Windows SmartScreen and macOS Gatekeeper will prompt — pilot with a small group first.

The Agent does not switch anyone's active background: no meeting platform lets a third party do that by API. Each employee selects the branded background once and Teams keeps it.

To remove it, uninstall the Agent from Add/Remove programs (Windows) or the Applications folder (macOS), and revoke the device in My team.

Questions

Can I deploy Teams backgrounds with Intune?

Yes. MeetingBrand generates an Intune script for Windows and a Jamf script for macOS in My team. It installs the MeetingBrand Agent, which places the company's approved background in each person's Teams background gallery; each person selects it once and Teams keeps it.

Do I need Teams Premium to deploy a company Teams background?

No. Teams Premium lets an admin upload organization backgrounds in the Teams admin center; without it, the MeetingBrand Agent delivers the background to each device.

What happens when we change the background?

Approve the new background in MeetingBrand; the Agent brings the change to each device without another deployment.

Will Windows or macOS warn about the Agent?

Yes, for now: the Agent builds are unsigned developer builds, so Windows SmartScreen and macOS Gatekeeper will prompt.

How do we remove it?

Uninstall the Agent from Add/Remove programs (Windows) or the Applications folder (macOS), and revoke the device in My team.

How do I deploy a custom Teams background to all users?

Deliver the image file to each device: new Teams lists a background only when <GUID>.png and a matching <GUID>_thumb.png sit in %LocalAppData%\Packages\MSTeams_8wekyb3d8bbwe\LocalCache\Microsoft\MSTeams\Backgrounds\Uploads. The MeetingBrand Agent writes that pair on every Windows and Mac after IT deploys it once with the Intune or Jamf script generated in My team; each person then selects the background once. Tenants with Teams Premium can instead upload organization backgrounds in the Teams admin center and require them.

Why is there no option to add a custom background in Teams?

Usually because the Teams meeting policy does not allow custom backgrounds (the video filters setting must allow all filters), or because the user is under a Teams Premium required-background policy. With custom images allowed, Add new appears under Effects and avatars → Backgrounds, and the Agent-delivered background appears in that gallery after Teams restarts.
